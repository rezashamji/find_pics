Blind eye audit of the complex-query benchmark's CANDIDATE answer sets (eval/complex_bench/audit.py).
Written BEFORE any sheet was looked at. Public DISBench (Flickr) photos only.

What is being measured
  For each request the benchmark holds a candidate answer set (truth program + 27B oracle). The audit asks, for a
  stratified sample of requests per category (test + dev splits, round-robin over libraries): does each sampled
  photo belong in the answer to the OWNER'S WORDS? Answers are mixed with in-scope NON-answers so the labeller cannot
  tell them apart:
    answer  : up to 6 random photos from the candidate set              -> precision of the set
    hard    : up to 4 non-answers among the 30 in-scope photos most similar to the words (PE-Core image-text)
              -> misses the set is most likely to have
    random  : 2 other in-scope non-answers                               -> misses elsewhere
  "in scope" = the photos the request's time/place/anchor/person constraints allow (so a missed photo is a real miss).

Sheets
  eval/complex_bench/audit/sheets/<name>_<k>.jpg: up to 6 photos per sheet at NATIVE pixels (DISBench photos are
  <= 500 px; that is also what the judges see). Each photo has a yellow number top-left and, under it, the camera date,
  weekday, local time and the city/region from its GPS address. Tiles marked "A" are the photo the request refers to
  (category e: the anchor the generator chose); they are not candidates.
  The labeller reads the requests from audit/requests.txt (words only: "q012_e [e] message 1 || message 2").
  NEVER open audit/key.json, queries/*.json, programs/*.json or oracle/* while labelling (unblinding).
  When a photo might hold a small thing, crop and enlarge that region with PIL (no new pixels; crops go to
  .cache/tmp/) before deciding.

Labels: one line per photo in audit/labels_<labeller>.txt:  <name> <number> <label> <short note>
  label = match | no_match | unsure  (category g: album0 | album1 | neither | unsure, album0 = the FIRST group the
  request names). Anchor tiles: "<name> A1 match|no_match <note>" = does this photo fit how the request describes the
  moment/thing it refers to, and is it plausibly the only such moment in what you can see.
  First line of the file: "# labels written blind from the sheets, before reading key.json".

Criteria
  - The whole request counts: subject AND look AND time AND place as stated. Use the date/time/place strip for
    time/place words ("last summer" is relative to the TODAY of the request, given in requests.txt).
  - Things: a REAL one visibly present, any size, unless the words say it is the subject ("photos of X", "X photos"
    -> X is a main element). Statues/paintings/toys only when the words ask for them.
  - Looks/colours/style: the stated look must be clearly visible (magenta = clearly magenta/pink-purple, not red;
    black and white = no colour at all; blurry = visibly out of focus/motion-blurred, not just soft).
  - People: count, clothing, activity as stated; for named people (Sam/Alex) a reference crop is shown: same person.
  - Multi-turn (h): judge against the request AFTER the last message (all edits applied).
  - Vague recollection (f): match = this photo is one the owner could plausibly mean; several matches on one sheet
    = the request is ambiguous (that is a finding, not an error of the labeller).
  - unsure only when the photo genuinely cannot be decided at this resolution or the criterion is borderline.

Scoring (audit.py score, after all labels are written)
  precision(category) = answer photos labelled match / answer photos labelled match or no_match (unsure reported).
  miss rate(stratum) = non-answers labelled match / labelled; estimated missed photos per request = hard-pool size x
  hard miss rate + rest-of-scope size x random miss rate (pooled per category); estimated recall = (answer size x
  precision) / (that + estimated missed). Categories whose precision < 0.8 or estimated recall < 0.7 are fixed
  (re-prompted / filtered) or dropped, and the report says which.
  A second labeller (independent Claude subagent, same protocol, never shown the key) labels an overlap of >= 20% of
  sheets; agreement is reported.

ADDED 10-16 (RESULTS 63, truth pass for b, c, g on dev + TRAIN), written and committed BEFORE any direct-judge answer,
disagreement count or score was seen. The TEST split stays closed (no request, truth or image of it is read).
  Opinions per UNIT = (request, album, photo); album 0 for b/c, albums 0 and 1 for g (album 0 = the first group named).
  Universe: every photo of the request's library; for a named-person album only photos where the bench's face match finds
  that person (the truth's own identity constraint, not re-derived).
    T = current truth (queries/<split>.json final album).
    D = Qwen3.5-27B-FP8 (the oracle model) asked the OWNER'S WORDS directly (t63/direct.py prompt: date/weekday/time/place
        strip + today + the request words; "does this photo belong in the answer / in the FIRST|SECOND group"), native
        photo, P(yes) >= 0.5. Asked on every unit.
    L = Qwen3.5-122B-A10B-FP8 (third opinion; RESULTS 58: .944 vs 27B .950 on held-out eye labels, the strongest larger
        open VLM here), same prompt, P(yes) >= 0.5, asked on every unit with D != T and on every eye-sampled unit.
  Strata per category (dev + TRAIN pooled): A11 (T=1, D=1); FADD (T=0, D=1, L=1) = flip candidates, add; KADD (T=0, D=1,
  L=0); FREM (T=1, D=0, L=0) = flip candidates, remove; KREM (T=1, D=0, L=1); agreed-out by D's P: N1 [.2, .5), N2
  [.05, .2), N3 < .05.
  Eye sample per category (seed 63, units drawn uniformly within stratum, at most one unit per photo): FADD 30, FREM 30,
  KADD 15, KREM 15, A11 15, N1 15, N2 10, N3 10 (fewer if the stratum is smaller). The main agent labels every sampled
  photo itself at native pixels (DISBench <= 500 px = what every judge sees) on shuffled sheets that do not show the
  stratum, the truth or any judge's answer, with the request words + today in a text list; labels written before
  t63/key.json is read; criteria as above (whole request: subject AND look AND time AND place; g: album0 | album1 | neither).
  FLIP RULE (per category x direction): all FADD units of a category are added to its truth iff the eye agrees with the
  flip (label = match) on >= 0.70 of the labelled FADD sample (unsure excluded, >= 10 labelled); likewise FREM units are
  removed iff the eye says no_match on >= 0.70 of the labelled FREM sample. Otherwise that stratum stays as it is. KADD
  and KREM (the larger judge sides with the truth) never flip. No other change to any truth.
  Requests: kept as they are; a request whose corrected album becomes empty is dropped from the corrected file (reported).
  VERIFIED RULE: a category becomes VERIFIED iff the corrected truth's pooled stratified estimate from the eye labels
  (TP = sum over in-truth strata of N_s x match share, FP = N_s x no_match share, FN = sum over out-of-truth strata of
  N_s x match share) reaches precision >= 0.80 AND recall >= 0.70; otherwise it stays PROVISIONAL. The same estimate is
  reported for T (old truth), D alone and L-on-disputes.
  NO PRODUCT RE-TUNING: the corrected truths are used only to RE-SCORE runs that already exist (shipped stack = R59d
  cascade + 2B 61b writer + repeat-stop v2, eval/facts_writer/replay/c61d_{dev,train}_t2b_final_rs2_xfit/r59d; the
  all-judge reference). No threshold, prompt, model or code of the product is changed on the basis of RESULTS 63.
